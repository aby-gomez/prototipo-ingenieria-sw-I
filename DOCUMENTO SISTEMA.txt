ESTRATEGIA DE ENTREVISTAS


Se utilizó la técnica de entrevista estructurada(estructura de embudo).
En base a las funcionalidades mínimas que se solicita del sistema direccionamos a la clienta hacia cada requerimiento particular, realizando tanto preguntas abiertas como cerradas para obtener una visión global del funcionamiento de este pero también obtener sus aspectos elementales.

CU-01: Iniciar sesión


Actor primario: Usuario
Alcance: Sistema del Laboratorio de Medios Audiovisuales.
Stakeholders:
   * Usuario: autenticarse para operar según sus permisos y roles asignados.
Precondiciones:
   * El usuario se encuentra previamente registrado.
   * La cuenta se encuentra en estado Activo.
Postcondiciones:
   * Se registra una sesión activa asociada a la cuenta del usuario.
Escenario principal:
1. El usuario accede a la pantalla de inicio de la plataforma web.
2. El sistema muestra el formulario de autenticación con los campos «Correo institucional» y «Contraseña», junto al botón «Iniciar sesión».
3. El usuario ingresa sus credenciales y presiona «Iniciar sesión».
4. El sistema verifica la validez de las credenciales y el rol asignado a la cuenta.
5. El sistema redirige al panel principal correspondiente al rol o roles del usuario.
Extensiones:
4a. Las credenciales ingresadas son incorrectas.
4a1. El sistema informa que el correo o la contraseña son incorrectos.
4a2. El sistema permite al usuario volver a ingresar sus credenciales.
4a3. Continúa en el paso 3 del escenario principal.
4b. Uno o más campos obligatorios están vacíos.
4b1. El sistema informa que se deben completar el correo institucional y la contraseña.
4b2. El usuario completa los campos y presiona «Iniciar sesión».
4b3. Continúa en el paso 4 del escenario principal.
4c. La cuenta se encuentra suspendida o inhabilitada temporalmente:
4c1. El sistema informa que la cuenta posee una suspensión activa (indicando motivo o   fecha de finalización) y no permite iniciar sesión.




CU-02: Registrarse


Actor primario: Usuario Académico. 
Alcance:  Sistema del Laboratorio de Medios Audiovisuales.
Stakeholders:
   * Usuario: Crear una cuenta vinculada a su identidad universitaria para acceder a las reservas y servicios del laboratorio.
   * Administración: Garantizar que solo miembros legítimos de la comunidad académica (alumnos/docentes) se registren en la plataforma.
Precondiciones:
   * No se requieren precondiciones.
Postcondiciones:
   * La cuenta de usuario queda registrada en el sistema con estado Activo.
   * Se habilitan las credenciales para el inicio de sesión.
Escenario principal:
1. El usuario accede a la pantalla de inicio de la plataforma web.
2. El sistema muestra la opción «Registrarse».
3. El usuario selecciona «Registrarse».
4. El sistema muestra el formulario con los campos «Nombre», «Apellido», «Correo institucional», «Contraseña» y «Confirmar contraseña», junto al botón «Crear cuenta».
5. El usuario completa los campos y presiona «Crear cuenta».
6. El sistema valida los datos ingresados y registra la cuenta.
7. El sistema le informa al usuario que el registro fue exitoso y redirige al usuario a la pantalla de inicio de sesión.
Extensiones:
6a. Hay datos inválidos o campos obligatorios incompletos.
6a1. El sistema informa qué campos deben completarse o corregirse.
6a2. El usuario corrige los datos y presiona «Crear cuenta».
6a3. Continúa en el paso 6 del escenario principal.
6b. Ya existe una cuenta asociada al correo ingresado.
6b1. El sistema informa que el correo ingresado ya está registrado.
6b2. El usuario ingresa otro correo institucional y presiona «Crear cuenta».
6b3. Continúa en el paso 6 del escenario principal.
6c. El correo ingresado no pertenece al dominio institucional.
6c1. El sistema informa que debe ingresar un correo institucional.
6c2. El usuario corrige el correo y presiona «Crear cuenta».
6c3. Continúa en el paso 6 del escenario principal.
CU-03: Configurar canal de notificaciones


Actor primario: Usuario Académico 
Alcance: Sistema del Laboratorio de Medios Audiovisuales.
Stakeholders:
   * Usuario Académico: elegir el medio preferido para recibir avisos del sistema.
Precondiciones:
   * El usuario se encuentra autenticado en el sistema.
Postcondiciones:
   * Se guarda la preferencia del canal de notificación del usuario.
   * Si el usuario cancela o no confirma cambios, se conservan las preferencias previamente configuradas.
Escenario principal:
1. El usuario selecciona «Configuración de notificaciones» desde el panel principal.
2. El sistema muestra la configuración de canales con las opciones «Correo electrónico» y «Notificación de la aplicación», junto al botón «Guardar» y «Cancelar»..
3. El usuario marca o desmarca los canales que desea utilizar y presiona «Guardar».
4. El sistema valida la selección y guarda las preferencias de notificación.
5. El sistema le informa al usuario académico que la configuración se guardó correctamente.
Extensiones:
       3a. El usuario cancela la configuración:
3a1. El usuario selecciona la opción «Cancelar».
3a2. El sistema descarta las modificaciones y retorna al panel principal.
4a. El usuario no selecciona ningún canal de notificación.
4a1. El sistema mantiene habilitada la notificación de la aplicación como canal predeterminado.
4a2. El sistema guarda la preferencia predeterminada e informa al usuario el resultado.




CU-04: Consultar catálogo de equipamiento
Actor primario: Usuario Académico
Alcance: Sistema del Laboratorio de Medios Audiovisuales.
Stakeholders:
* Usuario Académico: Conocer la disponibilidad y el stock de los equipos antes de realizar un pedido.
Precondiciones:
* El usuario se encuentra autenticado en el sistema.
Postcondiciones:
Escenario principal:
        
1. El usuario selecciona la opción «Catálogo de equipamiento» desde la página principal.
2. El sistema muestra el listado de equipos con nombre, categoría, disponibilidad y stock. Junto al listado muestra el campo de búsqueda, el selector de categoría, el selector de disponibilidad, el botón «Aplicar filtros» y el botón «Solicitar préstamo» en cada equipo. de cada equipo un casillero para tildarlo
3. El usuario ingresa un término en el campo de búsqueda y presiona «Aplicar filtros».
4. El sistema actualiza el listado mostrando únicamente los equipos coincidentes
        
Extensiones:
2a. El usuario decide solicitar un equipo:
        2a1. El usuario presiona «Solicitar préstamo» sobre un equipo.
        2a2. El flujo continúa en CU-07: Solicitar préstamo de equipamiento, con el         equipo seleccionado ya agregado a la solicitud.


3a. No hay equipos que coincidan con la búsqueda o los filtros aplicados:
3a1. El sistema informa que no se encontraron equipos para los criterios ingresados.
3a2. El usuario puede ajustar o limpiar los filtros y la búsqueda.
3a3. Continúa en el paso 4 del escenario principal.


 3b: el usuario filtra por categoría o disponibilidad.
   * 3b1: el usuario selecciona el filtro por categoria.
   * 3b2: presiona «Aplicar filtros».
   * 3b3: continúa en el paso 4.

4a1. El flujo continúa en CU-06: Gestión de préstamos.
4b. El usuario selecciona la sección «Reserva de aulas/estudios»:

CU-06: Gestiónar préstamos 


Actor primario: Usuario Académico 
Alcance: Sistema del Laboratorio de Medios Audiovisuales.
Stakeholders:
   * Usuario Académico: Ver el detalle de sus préstamos de equipos y acceder a las opciones para extender plazos o cancelar solicitudes.
Precondiciones:
   * El usuario se encuentra autenticado en el sistema.
Postcondiciones:
Escenario principal:
   1. El usuario accede a la sección «Préstamos de equipamiento» desde el panel de solicitudes.
   2. El sistema muestra el listado detallado de préstamos del usuario indicando fecha de solicitud, equipo, fecha límite de devolución y estado actual junto a un botón ”crear préstamo”.
   3. El usuario selecciona un préstamo específico para ver su detalle.
   4. El sistema muestra el detalle del préstamo con su estado actual y los botones «Solicitar extensión» y «Cancelar préstamo». 
   5. El usuario clickea en «Cancelar préstamo» continua en CU 09


CU-07: Solicitar préstamo de equipamiento
Actor primario: Usuario Académico
Alcance: Sistema del Laboratorio de Medios Audiovisuales.
Stakeholders:
   * Usuario Académico: Registrar su solicitud de equipamiento audiovisual según la gama del equipo solicitado.
   * Docente: Aprobar las solicitudes de gama media que lo indican como docente a cargo.
   * Administrador: Evaluar las solicitudes de equipamiento de gama alta.
Precondiciones:
   * El usuario se encuentra autenticado en el sistema.
Postcondiciones:
   * La solicitud queda registrada con su número identificador, fecha de creación, usuario solicitante, equipos y datos ingresados.
   * El estado de la solicitud es «Aprobada» (si es gama media), «Pendiente» (gama media para Materia Proyecto o gama alta).
   * Los equipos quedan reservados para la franja horaria solicitada.
   * Se notifica al usuario y, si la solicitud requiere aprobación, a quien debe resolverla.


Escenario principal:
   1. El sistema muestra el formulario de solicitud con los campos «Materia/Cátedra/Proyecto», «Docente a cargo», «Fecha de retiro y  fecha de devolución» y «Justificación». Muestra también el buscador de equipos con los filtros de categoría y disponibilidad, la lista de equipos de la solicitud y los botones «Confirmar solicitud» y «Cancelar». 
   2. El usuario ingresa un término en el buscador de equipos. 
   3. El sistema muestra los equipos que coinciden con la búsqueda, con el botón «Agregar» en cada uno. 
   4. El usuario presiona «Agregar» sobre un equipo e indica la cantidad.
   5. El sistema agrega el equipo a la lista de equipos de la solicitud, con el botón «Quitar» en cada uno 
   6. El usuario completa los datos del formulario. 
   7. El usuario presiona «Confirmar solicitud»
   8. El sistema valida que todos los equipos sean de la misma gama, que el plazo cumpla las condiciones de esa gama, que los equipos estén disponibles en la franja horaria indicada y que el usuario no posea bloqueos. 
   9. El sistema registra la solicitud, reserva los equipos, notifica al usuario y muestra un mensaje de confirmación indicando que la solicitud fue creada, junto con su número identificador. 


Extensiones:


1a El usuario ya tiene equipos seleccionados para la solicitud
1a1.. El sistema muestra el formulario con todo lo del escenario principal, con el filtro de fechas ya cargado y la lista con los equipos ya agregados. 
1a2. continúa en paso 2.
5a. El usuario intenta agregar un equipo de gama alta sin ser alumno de tercer año o superior, ni docente:
5a1. El sistema informa que el equipamiento de gama alta está reservado exclusivamente para alumnos de tercer año o superior y docentes.
5a2. Continúa en el paso 2 del escenario principal.
6a. El usuario quita un equipo de la solicitud:
   * 6a1. El usuario presiona «Quitar» en uno de los equipos de la lista.
   * 6a2. El sistema actualiza la lista de equipos de la solicitud.
   * 6a3. Continúa en el paso 6 del escenario principal.
7a. El usuario cancela la solicitud:
   * 7a1. El usuario presiona el botón «Cancelar».
   * 7a2. El sistema descarta la solicitud y vuelve al panel principal.

   * 3a2. El sistema actualiza el listado mostrando únicamente las tutorías coincidentes.
   * 3a3. Continúa en el paso 3 del escenario principal.
4a. La tutoría seleccionada no posee cupos disponibles:
   * 4a1. El sistema informa mediante un mensaje que la tutoría ha alcanzado el límite máximo de inscriptos.
   * 4a2. El sistema no registra la inscripción y permite al alumno seleccionar otro turno disponible.
4b. El alumno posee una penalización activa por inasistencias injustificadas:
   * 4b1. El sistema detecta la sanción en la cuenta del alumno e informa: “No es posible inscribirse a tutorías debido a una suspensión activa por inasistencias previas sin aviso”.
   * 4b2. El sistema bloquea el registro de la inscripción.
4c. El alumno ya se encuentra inscripto en la misma tutoría o en una actividad con superposición horaria:
   * 4c1. El sistema informa que el usuario ya registra un turno confirmado en esa franja horaria.
   * 4c2. El sistema cancela la operación y no registra la nueva inscripción.


CU-20: Solicitar rol de tutor


Actor primario: Usuario Académico


Alcance: Sistema del Laboratorio de Medios Audiovisuales.


Stakeholders:
   * Alumno: Postularse formalmente para obtener los permisos de tutor y poder dictar sesiones de apoyo a sus pares.
   * Administración: Evaluar el rendimiento académico del postulante y autorizar la asignación del rol.
Precondiciones:
   * El Usuario académico se encuentra autenticado en el sistema.
   * El usuario se encuentra autenticado en el sistema con el perfil de Estudiante.
Postcondiciones:
   * La solicitud queda registrada en la base de datos en estado «Pendiente de aprobación».
   * Se genera una alerta en el panel de administración para su evaluación.
Escenario principal:
   1. El alumno accede a su panel principal.
   2. El sistema muestra la opción «Solicitar rol de tutor» dentro de la sección de perfil o tutorías.
   3. El alumno selecciona «Solicitar rol de tutor».
   4. El sistema despliega el formulario de postulación con los campos: Año de cursada, Materias aprobadas, Materia(s) a tutorear, Historia académica / Comprobante (adjunto) y la fundamentación del pedido, junto al botón «Enviar solicitud».
   5. El alumno completa los campos obligatorios, adjunta la documentación de respaldo y presiona «Enviar solicitud».
   6. El sistema valida que los campos estén completos, que el alumno no posea una solicitud activa y que registre aprobadas las materias seleccionadas.
   7. El sistema registra la solicitud en estado «Pendiente de aprobación», emite un comprobante con el número de trámite y muestra un mensaje notificando que el pedido fue enviado correctamente.
Extensiones:
6a. El alumno ya posee el rol de tutor o registra una solicitud en trámite:
6a1. El sistema informa mediante un mensaje: “Usted ya cuenta con el rol de tutor activo o posee una solicitud pendiente de revisión”.
6a2. El caso de uso finaliza sin guardar registros duplicados.
6b. Existen campos obligatorios incompletos o falta adjuntar documentación:
6b1. El sistema resalta los campos requeridos faltantes e informa: “Por favor complete todos los campos obligatorios”.
6b2. El alumno completa los datos faltantes y reintenta el envío.
6b3. Continúa en el paso 6 del escenario principal.
6c. El alumno no registra como aprobada la materia que desea tutorear:
6c1. El sistema detecta que el postulante no cumple con el requisito académico para la materia elegida.
6c2. El sistema informa: “Para postularse como tutor debe contar con la asignatura aprobada en su historia académica”.
6c3. El sistema no permite enviar la solicitud para esa materia.


CU-21: Gestionar cuentas de usuario y roles
Actor primario: Administrador
Alcance: Sistema del Laboratorio de Medios Audiovisuales.
Stakeholders:
Administrador: Mantener el control de accesos, asignar roles y permisos especiales (por ejemplo, Tutor) y aplicar bloqueos y desbloqueos manuales.
Usuario Académico: Contar con un perfil actualizado que refleje sus permisos reales en la institución.
Precondiciones:
El usuario se encuentra autenticado en el sistema con el rol de Administrador.
Postcondiciones:
Se actualizan los roles de la cuenta de usuario seleccionada.
Si se bloquea la cuenta, su estado pasa a «Suspendido»; si se desbloquea, pasa a «Activo».
Cada modificación se registra en el historial de auditoría (fecha, hora y administrador que realizó el cambio).
Escenario principal:
   1. El administrador selecciona la opción «Gestión global de usuarios» desde el panel de administración.
   2. El sistema muestra la tabla de usuarios registrados con nombre y apellido, correo institucional, carrera/departamento, roles asignados y estado actual («Activo» o «Suspendido»). Junto a la tabla muestra el campo de búsqueda, los filtros por rol y estado, y el botón «Bloquear/Desbloquear» en cada cuenta.
   3. El administrador selecciona un usuario, elige el nuevo rol (por ejemplo, Tutor) y presiona «Guardar cambios».
   4. El sistema actualiza los roles de la cuenta, registra el cambio en el historial de auditoría y muestra un mensaje de confirmación.
Extensiones:
3a. El administrador busca o filtra usuarios:
3a1. El administrador ingresa un término en el campo de búsqueda o selecciona un criterio de filtro (rol o estado).
3a2. El sistema actualiza la tabla mostrando únicamente las cuentas coincidentes.
3a3. Continúa en el paso 3 del escenario principal.
3b. El administrador bloquea o desbloquea una cuenta:
3b1. El administrador presiona «Bloquear/Desbloquear» sobre la cuenta seleccionada.
3b2. El sistema muestra una ventana con el campo «Motivo» y los botones «Confirmar» y «Cancelar».
3b3. El administrador ingresa el motivo y presiona «Confirmar».
3b4. El sistema actualiza el estado de la cuenta a «Suspendido» (si se bloquea) o «Activo» (si se desbloquea), registra el cambio en el historial de auditoría y muestra un mensaje de confirmación.
3b5. Continúa en el paso 2 del escenario principal.
3c. El administrador cancela el bloqueo o desbloqueo (en 3b2):
3c1. El administrador presiona «Cancelar».
3c2. La cuenta conserva su estado previo sin alteraciones.
3c3. Continúa en el paso 2 del escenario principal.

CU-28: Autorizar renovación de préstamo regular

Alcance: Sistema del Laboratorio de Medios Audiovisuales.

   * Usuario Académico: Ser informado sobre el resultado de su solicitud de renovación.
Precondiciones:
   * El usuario se encuentra autenticado en el sistema con el rol de Colaborador.
   * Existe al menos una solicitud de extensión en estado «Pendiente de renovación».
Postcondiciones:
   * Si se aprueba, la fecha de devolución del préstamo se actualiza (ajustada al primer día hábil si cae en fin de semana), la solicitud queda en estado «Aprobada» y se notifica al usuario solicitante.
   * Si se rechaza, la solicitud queda en estado «Rechazada», el préstamo conserva su fecha de devolución y se notifica al usuario solicitante.

   1. El colaborador selecciona la opción «Solicitudes de renovación» desde el panel principal.
   2. El sistema muestra el listado de solicitudes de renovación pendientes, con el usuario, el equipo, la fecha de devolución actual y la nueva fecha propuesta. Cada solicitud tiene los botones «Aprobar» y «Rechazar».
   3. El colaborador selecciona una solicitud y presiona «Aprobar».
   4. El sistema verifica que el equipo no tenga reservas conflictivas en el nuevo período.
   5. El sistema extiende la fecha de devolución del préstamo (si cae en fin de semana, la fija el lunes siguiente a las 09:00 hs), actualiza el estado de la solicitud a «Aprobada», notifica al usuario solicitante por su canal de notificación configurado y muestra un mensaje de confirmación.
Extensiones:
3a. El colaborador rechaza la solicitud:
   * 3a1. El colaborador presiona «Rechazar».
   * 3a2. El sistema actualiza el estado de la solicitud a «Rechazada», mantiene la fecha de devolución del préstamo, notifica al usuario solicitante por su canal de notificación configurado y muestra un mensaje de confirmación.
   * 3a3. Continúa en el paso 2 del escenario principal.
4a. El equipo tiene una reserva conflictiva:
   * 4a1. El sistema informa que no se puede aprobar la renovación porque el equipo ya fue reservado por otro usuario.
   * 4a2. La solicitud conserva su estado previo sin alteraciones.
   * 4a3. Continúa en el paso 2 del escenario principal.
